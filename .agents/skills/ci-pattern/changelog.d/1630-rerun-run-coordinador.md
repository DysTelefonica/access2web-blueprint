Asset nuevo `assets/runner-controls/rerun_run.py`: el coordinador del repositorio relanza un run cancelado o caído con un solo comando (`--repo <owner/name> --run <id>`), con el `gh` de `$CI_PATTERN_GH` o del PATH (#1609). Antes de relanzar comprueba que el run es del repo, que terminó `cancelled`, `failure` o `timed_out` y que su SHA sigue siendo la cabeza de su PR o de su rama; si no, sale con 2 y dice el motivo, y con un SHA viejo pide empujar. Relanza con `--failed` (`--all-jobs` relanza el run entero) y la última línea dice el resultado. La fila «El rojo exige un push de corrección» del §3 lo recoge: el colaborador pide el relanzamiento y cerrar y reabrir el PR SÍ relanza la CI, pero no es el relanzamiento oficial: se pide al coordinador. Los mensajes de `check_governed_merge.py` y `wait_ci.py` para una base cambiada piden ahora un commit vacío en vez de cerrar y reabrir el PR. Refs #1630.
