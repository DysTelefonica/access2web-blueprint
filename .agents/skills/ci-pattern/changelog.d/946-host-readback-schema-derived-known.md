`check_host_drift` rechazaba contratos cuya clave top-level no figuraba en un `frozenset` literal al lado del módulo (#946): bastaba que el canon añadiera una clave —por ejemplo `post_merge_dispatch` en HR-817 (#805 PR3)— para que el gate fallara cerrado con `contract has unknown keys: [...]` aunque el resto del canon ya la conociera (SKILL.md y `parameters.md`). Ahora el módulo carga `host-contract.schema.json` junto al script y deriva el set `known` de `properties`, así que añadir una clave al canon se reduce a editar el schema: una sola fuente de verdad. La regresión queda fijada por un segundo test que asegura que una clave que sigue sin estar en el schema mantiene `rc=2` con el mismo mensaje previo. Si el schema falta o está malformado al cargar el módulo, el gate falla cerrado (HR-3).
