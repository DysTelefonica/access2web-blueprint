#941: los stubs HTTP que sustituyen a la API de GitHub en los tests de ci-pattern (`runner-controls/_github_stub.py`, `pr-size/test_check_pr_size.py::_Api`, `bin/test_pr_preflight.py::_IssueApiStub`, `migrations-immutable/test_migrations_immutable_reserved.py::_MockHandler`) llevaban estado mutable a nivel de clase o Handler anidado en `__init__`, lo que hacia que `testing/run-unit-suites.sh` con `UNIT_PARALLEL>1` (#511) mezclara respuestas entre clases y disparara `KeyError: 'page'` cuando una clase de test enviaba una URL no paginada. Cada Handler pasa a fabricarse con una funcion de cierre (`_make_handler` / `_issue_api_handler` / `_make_mock_handler`) que captura su estado por instancia, sin atributos de clase; los tests crean su propio dict (`self.mock_state`, `self.issues`) en `setUp`. `_Api` enruta por path y devuelve 404 explicito cuando la URL no es `/pulls/N/files?page=&per_page=`. Ninguna suite se relaja a serie ni anade reintentos: el paralelismo del runner y la mediana del job se mantienen.
