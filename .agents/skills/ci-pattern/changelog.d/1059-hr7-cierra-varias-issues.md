HR-7 (#1059) dice ahora **cuáles** issues cierra el cuerpo del PR, no solo si cierra alguna. El gate comparaba `has_closes = bool(rx.search(body))`: en cuanto encontraba un `Closes #N` daba el visto bueno y no volvía a recorrer el cuerpo, así que un PR punta que declaraba `Closes #1056` y que además nombraba `Closes #1035` al citar un ejemplo pasaba igual, y GitHub cerraba las dos al mergearse. Pasó con la PR 1058 de este repositorio: su `closingIssuesReferences` llegó a `[1035, 1056]` y, de no leerlo antes del merge, habría cerrado la issue 1035, que tenía trabajo pendiente. La causa no fue el formato: una palabra de cierre pegada a un número cierra esa issue en GitHub, y el gate no ayudaba a verlo. Ahora `check_closes` recorre todas las coincidencias con las nueve palabras clave de GitHub y, **cuando el cuerpo apunta a más de una issue y el PR no es un `chain:partial`**, imprime por `stderr` la lista completa: `HR-7 AVISO: el cuerpo cierra 2 issues (#1035, #1056); GitHub las cerrará todas al mergearse…`. El **veredicto no cambia**: cerrar varias issues en un PR punta es legítimo, así que la lista es visibilidad, no un hallazgo, y ningún consumer se pone rojo por esto —que es justo lo que la issue fijaba como no objetivo—. Con `chain:partial` no se toca nada: ahí la palabra de cierre ya es el fallo de HR-7. La lista sale solo si hay más de una issue, de modo que un PR normal no paga ruido, y la misma issue citada dos veces (`Closes #1056` más `Fixes #1056`) cuenta una sola vez. El texto es el mismo cuerpo que el gate ya tenía en memoria: ninguna llamada nueva a la API, ninguna clave nueva en el contrato `checks`. Tests: el cuerpo con dos issues distinto reporta las dos, el cuerpo con una sola no dice nada, y la repetida no cuenta como lista.

Pendiente fuera de este cambio: la causa raíz —escribir el caso del bug con la palabra de cierre pegada al número— es de quien redacta, y no la atrapa ningún gate sin ruido. La nota reduce la sorpresa; la regla de redacción (nunca citar `Closes #N` al explicar un ejemplo, ni dentro de un span de código) queda como criterio de revisión.
