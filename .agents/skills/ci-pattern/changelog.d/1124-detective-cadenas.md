#1124: el detective post-push (`assets/runner-controls/check_push_compliance.py`) ya no marca como incidente una cadena de PRs fusionada en orden. Cuando la punta del push a una rama protegida es el merge commit o el head de una PR fusionada en esa rama, los commits del rango `base..merge` de esa PR quedan cubiertos. Para encontrar esa PR cuando `GET /commits/{sha}/pulls` solo devuelve la PR anterior de la cadena, el detective consulta también `GET /pulls?state=closed&base={rama}`; el cliente REST pagina ese listado con query. Un push directo a la rama protegida sigue abriendo incidente. La auditoría de la punta conserva los controles de checks, `governed_path` y `tracker_branch`; la integridad del árbol se sigue aplicando cuando la punta es el commit de merge.
