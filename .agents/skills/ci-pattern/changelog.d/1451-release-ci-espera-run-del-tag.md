`check_release_ci.py --wait-minutes N` espera hasta N minutos a que termine el run medido o, con `--tag-run`, a que aparezca el run del push del tag (#1451). Un run rojo, una API caída o un tag inexistente no esperan; al vencer el plazo el veredicto es el de antes. La plantilla `release.yml.tmpl` añade `CI_TAG_RUN` y `CI_WAIT_MINUTES` al bloque `env` (por defecto `"false"` y `"0"`, que dejan el comportamiento de antes) y amplía el plazo del job `preflight` a 120 minutos. El gate rechaza un `--wait-minutes` negativo o no finito, el paso rechaza un `CI_TAG_RUN` que no sea `true` ni `false`, y un bloque `env` antiguo sin los dos parámetros funciona como antes. Sirve a los consumers cuyo CI solo ejecuta una suite en el push del tag: el release y ese CI arrancan con el mismo push y, sin espera, el gate siempre encontraba el CI en curso.
