Issue-spec (#830): el modo `pr-event` ya no lee el cuerpo del PR desde `payload["pull_request"]["body"]` — esa instantánea queda obsoleta tras la primera edición del cuerpo y tras cualquier «Re-run jobs» del UI (que reusa el mismo `$GITHUB_EVENT_PATH`), dejando el gate en rojo aunque el cuerpo en GitHub ya esté bien (ardelperal/APAP_WEB#2163, #2164). El cuerpo se trae ahora por API con `GET /repos/{owner}/{repo}/pulls/{n}` vía el `GitHubClient` del asset. Sin `GITHUB_TOKEN` el gate falla cerrado (exit 2) nombrando la causa; con la API caída idem y expone el `GitHubPullRequestFailedError`. El modo `local` no cambia (sin payload, sin token, sin red). El contrato del modo `pr-event` gana la función pública `pr_event(payload, *, body_fetcher=None, issue_fetcher=None, …)` para que los tests y futuras extensiones inyecten los fetchers sin tocar el binario.
