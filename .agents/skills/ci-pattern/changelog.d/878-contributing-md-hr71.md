HR-71 (#878): `CONTRIBUTING.md` canónico para consumers `primary_type:web`. El manifiesto `assets/docs-manifest/required-docs.json` declara el documento con `activated_by: "project_type:web"`; el gate (`_active`, `_resolve_project_type`) lee `project_type` del `.team-skills.yaml` del repo y, si el YAML falta, no se puede leer o no declara `project_type`, falla cerrado (HR-3) emitiendo el hallazgo y activando el doc para que la ausencia del fichero también se mida. `routing_rows` acepta ahora `repo` opcional para activar `project_type:<x>` desde el enrutado de `AGENTS.md`. Plantilla canónica en `assets/templates/docs/CONTRIBUTING.md.tmpl`; `slices/partials/web.md` cita `CONTRIBUTING.md` como lectura obligatoria antes de abrir una PR. El catálogo **no** sobrescribe ni sella `CONTRIBUTING.md` en `.governance-manifest.json`; la fase 0 sigue exigiendo la entrada `{artifact: "CONTRIBUTING.md", disposition: "adopted", target: "CONTRIBUTING.md"}` en `phases[0].inventory` del contrato del consumer para silenciar el hallazgo de «artefacto de gobierno sin entrada de inventario».
