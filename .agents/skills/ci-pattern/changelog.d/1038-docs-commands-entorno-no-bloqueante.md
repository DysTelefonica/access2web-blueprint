HR-65 (#1038): la CLI ausente deja de ser roja cuando el control es presence-only **por construcción**. Sin `dry_run_flag` ni verbos en `executed_verbs` declarados, `_tier` devuelve `presence-only` para todo comando y el gate no ejecuta nada, así que una CLI que no está en el runner no puede estar ocultando ninguna medición: el runner de APAP#2324 (`{"cli_name": "make", "cli_command": ["make"]}`, `make` ausente) salía exit 1 con 58 comandos que nadie iba a probar. Ahora el mismo texto, el mismo nombre de CLI y el mismo remedio salen por `stderr` con prefijo `AVISO` y el job sale 0. Sigue siendo bloqueante, con el mismo hallazgo de siempre, en cuanto la política declara `dry_run_flag` o `executed_verbs` (ahí el gate sí tenía algo que ejecutar) y cuando la CLI resulta lanzable pero revienta al arrancar (`CliAusenteError`), que no se relaja. El resumen por nivel no depende de que la CLI esté o no. Sin claves nuevas en el contrato: el predicado es el de `_tier`, no una declaración nueva.
