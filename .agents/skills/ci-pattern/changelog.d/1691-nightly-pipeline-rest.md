`assets/prerelease/nightly_pipeline.py` deja de ejecutar el CLI `gh` y lee la API de GitHub con `runner-controls/github_rest.py` (urllib, stdlib), como ya hacen `stop_the_line.py` y `check_governed_merge.py`: el runner del consumer no trae `gh` (#1691), así que el gate de la canalización nocturna no podía correr en su CI. Se conserva el contrato del asset —mismos argumentos, mismos códigos de salida, mismos mensajes y el mismo fallo cerrado ante cualquier lectura fallida— y solo cambia el transporte: los jobs de todas las páginas se siguen por la cabecera `Link` en lugar de `--paginate`, y el token se toma de `GITHUB_TOKEN` o `GH_TOKEN`. El seam `CI_PATTERN_GH` desaparece de este asset; los tests pasan a hablar con el servidor stub de `runner-controls/tests/_github_stub.py` (`GITHUB_API_URL`) con el PATH vacío, de modo que un `gh` real en la máquina no puede validar el script. Refs #1691.
