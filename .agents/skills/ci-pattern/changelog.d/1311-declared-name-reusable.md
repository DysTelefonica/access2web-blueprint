El gate `workflow-policy` reconoce el nombre de check que publica un workflow reutilizable (DysTelefonica/team-skills#1311). Con `--host-contract`, un check que llega de un workflow reusable lo publica GitHub con el nombre compuesto `<job que llama> / <job llamado>` (medido: `pr-size / pr-size` y `pr-contract / pr-contract` en DysTelefonica/cadete; `pr-gate / pr-gate` y `security (pull_request) / gitleaks` en DysTelefonica/access2web-blueprint). El gate emparejaba el contrato solo con el nombre propio del job, así que reportaba esos checks como «no los publica ningún job analizado» y dejaba el job que sí los publica fuera del alcance de HR-30 para `schedule`/`workflow_dispatch`: un check que el host exige podía publicarse desde una corrida que no evalúa el pull request sin que el gate lo dijera. Ahora cada job declara sus nombres publicados —el propio, `<llamador> / <job>` si vive en un workflow reutilizable y `<este job> / <job llamado>` si llama a uno— y el contrato casa contra cualquiera de ellos, con el mismo comodín `${{ }}` de siempre. El nombre compuesto solo se declara cuando se puede PROBAR: si el workflow llamado no está entre los ficheros analizados (o es remoto) no se compone ningún nombre y el finding «host contract requires check '...' but no analyzed workflow job publishes it» se mantiene (fail closed). Sin la opción `--host-contract` el comportamiento no cambia.
