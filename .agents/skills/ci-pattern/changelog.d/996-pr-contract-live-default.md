El gate `pr-contract` lee ahora las etiquetas y el cuerpo del PR por API (vivos) por defecto cuando juzga el evento real de Actions: `--event-file` es `GITHUB_EVENT_PATH`, el payload es de un `pull_request` y hay `GITHUB_TOKEN` o `GH_TOKEN`. Antes el modo vivo era opt-in (`PR_CONTRACT_USE_LIVE_API=1`) y un PR etiquetado después de abrirse fallaba HR-6 (o A1 con `size:exception`) con la etiqueta ya puesta, hasta cerrar y reabrir el PR (CADETE #588 y #597). `PR_CONTRACT_USE_LIVE_API=0` es el opt-out explícito, `=1` sigue forzando la API y, con la API caída o rechazada, el gate falla cerrado (exit 2). Los scripts locales, el propagador y la suite de parity pasan su propio fichero de evento y no cambian. Los consumers que ejecutan el gate en CI con token pasan a depender de la API en cada evento (#996).
